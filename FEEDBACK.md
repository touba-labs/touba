# Feedback

Use GitHub Issues for feedback, questions, bug reports and proposals.

## Useful Feedback Includes

- the repository and version or commit involved;
- the intended result;
- what happened instead;
- minimal reproduction steps, when applicable;
- relevant logs, traces, screenshots or examples;
- the impact on your workflow.

## Conceptual Feedback

For language, runtime, governance, skills, documentation or product feedback,
describe the real use case first. Then explain the limitation, risk or missing
capability you encountered.

Good feedback helps distinguish:

- a bug in existing behavior;
- a documentation gap;
- a missing developer experience;
- a product requirement;
- a research or design question.

## Security Feedback

Do not report exploitable security issues in a public issue. Use the process in
`SECURITY.md`.
