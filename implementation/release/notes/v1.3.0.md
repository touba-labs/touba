# Touba 1.3.0

## Executive Summary

Local candidate for operation-bound approval and handler diagnostics. Public
downloads and previous archives are unchanged.

## Added

- Tools can declare `human.approve` with a role, deadline and signer separation.
- Each protected invocation requires approval of its exact arguments across
  direct calls, skills, agents, imports and concurrent branches.
- Handler context exposes the run, caller, active agent and agent invocation.

## Changed

- LSP hover and Explorer details show the approval requirement.
- CLI help documents the durable effect journal.

## Fixed

- Both SDKs preserve safe CLI admission and interrupted-execution diagnostics.
- Python preparation identifies symbolic `.venv` and SDK paths explicitly.

## Security And Governance

Approvals use trusted host attestations and a private single-use runtime permit.
Existing grant, secret, memory-scope and budget checks remain required.
Checkpoint integrity, replay and concurrent consumption checks are exercised.

## Breaking Changes

Update the runtime and handler SDK together. The new `execution_context` request
field can be rejected by older SDKs with closed request schemas. New AIR declares
`tool_operation_approval` in `required_features`; older runtimes reject it.

## Migration

Install the matching JavaScript or Python SDK with `touba sdk install javascript`
or `touba sdk install python`. Restart application services explicitly after
updating their dependencies. Keep suspended executions with their original build.
Declare approval on the tool when every path to that operation requires review.

## Validation Evidence

Source qualification includes 199 compiler tests, 486 runtime tests, 253
JavaScript SDK tests, 71 installed Python SDK tests and 265 project-server tests,
plus targeted additions, grammar, CLI, contracts and documentation checks.
The runtime suite excludes 12 tests reserved for other operating systems.
Archive installation and editor checks belong to each candidate's build receipt.

## Known Limits

Tool approval resumes through human checkpoints, including server restart.
The linear `RESUME-1` profile rejects this nested continuation before effects.
An interrupted external payment requires reconciliation with its service.
Business amount/vendor checks and cross-run invoice uniqueness belong to the
application service. SQLite test transactions do not make network payments atomic.
