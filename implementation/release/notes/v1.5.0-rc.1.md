# Touba 1.5.0-rc.1

## Executive Summary

Local test candidate for reviewed project lifecycle and governed execution.
The compiler, runtime and both SDKs share this distribution version.

## Added

- Reviewed project fleet plans, owned foreground processes and bounded shutdown.
- Idle-project upgrades with state archives, verified SDKs and durable step receipts.
- Typed server profiles, service credentials in the operating-system vault and validation-plan generation.
- Private operation dossiers for authorized signers and explicit registry-trust review.

## Changed

Scheduler failures retain bounded reason codes. Project preparation presents
effective trigger limits and preserves stricter operating limits.

## Fixed

Approval expiry invalidates pending decisions. Persisted human waits, source
diagnostics and Python/JavaScript validation keep their original failure causes.
Execution traces distinguish paused operations from completed work.

## Security And Governance

Fleet actions require a review of exact sources and profiles. Active operations
and pending approvals block the affected upgrade. Service credentials remain
outside process arguments. Review of registry trust preserves revocation continuity.

## Breaking Changes

Pending execution state remains tied to its original toolchain. New profile and
fleet contracts require this matching candidate; older tools reject unknown fields.

## Migration

Preserve the original toolchain and state. Complete or explicitly resolve pending
operations before upgrading. Review the archive and preparation plan, install
matching SDKs, then exercise the application using synthetic data.

## Validation Evidence

Source suites exercise preparation, admission refusals, private dossiers, real
local supervision, archival and stale-review rejection. Artifact qualification
is recorded separately against the candidate's exact source and file digests.

## Known Limits

This candidate is for local testing. Multi-platform qualification and public
publication remain separate steps. A supervisor process status describes its
child process; the project's connection and health are checked independently.
