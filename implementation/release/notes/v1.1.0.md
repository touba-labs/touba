# Touba 1.1.0

## Executive Summary

Touba 1.1.0 adds verified toolchain updates and improves project exploration,
approval recovery, SDK diagnostics and execution evidence.

## Added

- `touba update --check` checks the signed distribution catalogue.
- `touba update` installs a verified build after confirmation.
- `touba update --rollback` restores the retained build without a network call.

## Changed

- Project Explorer improves resource details, budgets and navigation.
- The graphical trace reader is kept internal while it matures. Execution
  traces, their storage and their programmatic readers remain available.
- JavaScript and Python SDKs follow the same host contracts and diagnostics.

## Fixed

- Approval checkpoints reject altered content, changed host contracts and replay
  across processes sharing the checkpoint store.
- Composition respects declared authority outside agent bodies as well.
- Provider and SDK diagnostics retain structured causes and source locations.
- Windows updates recognize short and long paths to the same installation.

## Security And Governance

Approved continuations are bound to their program and host contract. Successful
consumption is recorded durably. Changing a checkpoint or reusing the same
consumed approval is refused before another effect is dispatched.

This protection covers the recorded operation. Applications must still use
business idempotency keys when two distinct requests refer to the same payment.

Updates verify HTTPS origin, catalogue signature, sequence, expiry, file size,
checksum and payload identity before activation. The previous build is retained.

## Breaking Changes

Suspended executions from an earlier build are not migrated automatically.
Unprotected, modified or host-contract-incompatible checkpoints are refused.
Applications consuming detailed trace events should update their matching SDK.

## Migration

1. Back up project state and stop services using the installation being updated.
2. Complete valid pending operations with their original build and unchanged
   approved contract, or reconcile their effects before requesting a new approval.
   Do not edit checkpoints or replay payments to bypass a refusal.
3. Install Touba 1.1.0 once from Touba Downloads. Earlier public builds do not
   contain the verified updater. Later releases can use `touba update`.
4. Update each project's JavaScript or Python SDK explicitly and run its tests.
   Toolchain updates leave projects, SDKs and package locks unchanged.

Rollback restores executable files, not business data. After a machine failure,
use a verified installer and the retained build to recover the installation.

## Validation Evidence

The native qualification workflow exercises the packaged compiler and runtime,
checkpoint tampering and replay, both SDKs, fresh installation, signed-catalogue
updates and offline rollback on the four supported platforms. Distribution
checksums identify the exact delivered files.

## Known Limits

The Windows installer has no publisher certificate yet and may trigger
SmartScreen reputation warnings. Follow the Windows installation guide and
verify the download source. Native Windows handler confinement remains under
development. Public package hosting is being validated; local packages are
available. The runtime is JavaScript; the compiler is Rust.
