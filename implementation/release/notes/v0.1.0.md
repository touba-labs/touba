# Touba 0.1.0

Historical record only. This private prototype's release assets and tags were
removed on 2026-10-18 by maintainer decision. The text below describes its
original intended release scope, not a currently available public version.

## Executive Summary

Touba `0.1.0` explored the initial release scope for governed agentic
programming. It defines the public language surface, the AIR execution
contract, the CLI distribution path, structured traces, governed triggers and
the first registry and library foundations for reusable capabilities.

## Added

This release introduces typed Touba declarations for `tool`, `skill`, `agent`,
`strategy`, memory scopes, human approval, user interaction, triggers and
imports. Programs compile from `.tb` source to AIR, then execute through the
runtime with authority checks, manifests, grants, secret handles, payload
constraints and run budgets.

The `touba` CLI facade now covers compile, run, inspect, manifest generation,
handler stubs, project preparation, registry resolution, MCP import, REST
scaffolding, audit, supply-chain validation, version, doctor and update-policy
commands.

The planned distribution covered macOS Apple Silicon, macOS Intel, Linux
x64 and Windows x64, with `SHA256SUMS` and `CHECKSUMS.json`.

## Changed

Package versions report `0.1.0` across the public Touba components instead of
placeholder `0.0.0` values. `touba version --json` reports concrete component
versions, protocol versions, feature versions and the distribution channel.

The release model now separates source development, local archive validation and
GitHub Release publication. `touba update` is an update-policy diagnostic in
this release: it reports the expected archive and reinstall commands without
performing automatic replacement.

## Fixed

The V1 packaging path includes the public trigger ingress service, so installed
archives expose the command surface reported by `touba doctor`.

Release assets are generated with explicit version metadata, platform metadata
and checksums. The public release workflow assembles a single checksum set for
the published archive family.

## Security And Governance

The runtime executes AIR only and checks declared authority before external
effects. Secret values are represented through handles, payload boundaries are
declared explicitly, and traces expose structured execution evidence without
requiring raw payload disclosure.

Trigger ingress supports authenticated HTTP request handling, HMAC validation,
persistent queue and state files, replay rejection, rate limits and source-level
payload mapping for request triggers.

Supply-chain validation and registry metadata establish the first versioned path
for checking package and handler integrity before execution.

## Breaking Changes

None. This is the first public release line.

## Migration

Install Touba from the archive that matches the target platform, then run:

```sh
touba version --json
touba doctor --json
```

If an older local build reports `0.0.0` or `unknown`, reinstall from the
`0.1.0` archive with replacement enabled and open a new terminal.

## Validation Evidence

The release gates include package-version validation, release-index validation,
release-note validation, release metadata tests, native archive packaging,
fresh-install smoke checks, `touba version --json`, `touba doctor --json`,
runtime tests, CLI tests and Hub catalog validation.

The release pipeline records the final archive digests in `SHA256SUMS` and
`CHECKSUMS.json`.

## Known Limits

Automatic self-update is not enabled in `0.1.0`; users reinstall from a newer
archive or from a future package-manager channel. Code signing, notarization and
package-manager publication are release hardening tracks after the initial
GitHub Release channel.
