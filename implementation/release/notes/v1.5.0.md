# Touba 1.5.0

## Executive Summary

Local candidate for reviewed project lifecycle and governed execution. Compiler,
runtime and SDKs share this version. Publication remains a separate qualification.

## Added

- Reviewed multi-project lifecycle, typed server profiles and idle-project upgrades.
- Project request ingress sharing the configured hosts, approvals and effect journal.
- Paginated queue review with explicit reasons and state-bound confirmations.
- Private operation dossiers for authorized signers and verified registry trust.
- Signed compatibility metadata in registry catalogue pages before archive download.
- Explicit module/package ownership inheritance and revision-bound review receipts.
- Bounded discovery of explicitly approved local MCP servers, separate from import.
- Reviewed restoration of a known generated binding projection with a recovery journal.
- Reviewed package updates with before/after tool contracts and exact code digests.
- Bounded sequential submission of package suites into private drafts.
- JavaScript and Python helpers for resolving declared, locked package resources.
- Explicit registry status synchronization, signed offline cache and withdrawal warnings.
- Typed host configuration for package handlers, separate from their secrets.
- Author-declared dependency ranges in the versioned package v2 manifest, with exact locks and reviewed closure updates. JavaScript and Python resource resolvers share the same bounded comparator rules.
- Update previews show all changed packages and the constraints of installed consumers. Incompatible selections are refused before application.
- One reviewed update set can select multiple roots from explicit local archives or independently trusted registries. Installation keeps exact versions and rolls back the entire set on failure.
- Offline state adoption checks compatible, idle projects, backs up exact bytes and records a separate build transition while preserving historical traces. Pending work and unknown stores remain blockers.
- Versioned project APIs expose installed package declarations and signed catalogue status, freshness and compatible update candidates without activating handlers.
- Reviewed mixed package selections can add, retain and update roots together while preserving declared compatibility and exact locks.
- Explicit synthetic effect scenarios in JavaScript and Python test replay, lost replies and mandatory reconciliation. A reusable package includes service-side write counts and deficient-handler negative controls.

## Changed

Webhook signature v1 covers the timestamp, event identity, HTTP method, request
target and exact body. Mapped inputs are checked before durable acceptance.
Scheduler pause and resume govern future occurrences independently of pending work.
Package tests run from a clean archive. Generated test projects support reviewed
host decisions and an explicit effect journal without changing the author's tree.
Package commands accept an explicit French or English locale for authentication
and actionable diagnostics.

## Fixed

Package contract tests can import this toolchain's SDK and testing helpers
without inheriting the author's dependency tree. Invalid selected source or
AIR preserves its diagnostic instead of being reported as an absent input.
Package suites share one temporary identity per registry and revoke it after the
lot. Token refresh preserves the original session deadline; failed cleanup is
reported without hiding successful submissions. Canonical archive checks expose
exact dependency edges and publication refusals list blockers in dependency order.
Previously reviewed host effect contracts remain recognized when another source
fails compilation. Diagnostics preserve the primary error and expose conflicting
package requirements without including private runtime values.

Quota failures return 429 and terminal duplicates return 409. Accepted events
retain their durable state across quota races. Schedule revisions recheck limits.
Fleet failures retain bounded causes; missing credentials differ from identity
service outages. Package diagnostics identify the required and installed versions.

## Security And Governance

Uncertain effects require reconciliation and are never automatically replayed.
Private approval arguments stay outside queue listings, notifications and general
traces. Plans, review digests and requester authorization are checked again before
mutations. Strict prerelease compatibility remains unchanged.

## Breaking Changes

Existing webhook emitters must adopt signature v1. New server-profile and queue
contracts require matching clients. Pending runs remain tied to their original
toolchain and state.

## Migration

Keep the original toolchain and resolve pending runs before upgrading a project.
Review its state archive and preparation plan, install the matching SDK and test
with synthetic data. Enable project ingress explicitly with `--request-triggers`
and `--webhook-signature-secret-env NAME`. Standalone queues remain separate;
their pending work is not imported or replayed automatically.

## Validation Evidence

Source tests cover typed admission, signatures, quotas, JS/Python approval hosts,
restart recovery, queue review, stale plans and compatible catalogues. Exact
archive and native qualification receipts are retained with each local build.

## Known Limits

This is a local candidate. Other platforms and public distribution require their
own qualification. A 202 response confirms durable acceptance, not a successful
business outcome. Application-level correctness remains the application's duty.
Passing author tests does not certify a connector's remote provider or all effect
paths. Effect conformance tests use synthetic services; provider-side atomic
deduplication and reconciliation remain required by the chosen retry contract.
Cached withdrawal warnings report known status and freshness without stopping
an installed run or consulting the network implicitly.
