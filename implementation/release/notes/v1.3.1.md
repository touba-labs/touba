# Touba 1.3.1

## Executive Summary

This update brings operation-bound tool approval, prepared resources and
host-controlled compensation to users of Touba 1.1.0. It also corrects imported
approval requirements, tool-call accounting and SDK diagnostics. The runtime
and both SDKs use version 1.3.1.

## Added

- Tools can require human approval of their exact arguments, with a role,
  deadline and separation of signers. This applies to direct, composed,
  imported and agent-selected calls.
- JavaScript and Python handlers receive execution provenance: run, caller,
  active agent and agent invocation.
- Both SDKs expose host-controlled compensation creation and resumption.
- Hosts can explicitly activate declared triggers and lower their limits.

## Changed

Project entry refusals retain their controlled diagnostic code through the CLI,
JavaScript process/persistent transports and Python synchronous/asynchronous APIs.
Prepared resource bindings reach CLI, SDK and project-server execution with
fingerprint checks and per-call permissions. Unknown manifest and host
configuration fields are reported. LSP hover and Explorer show tool approval
requirements.

## Fixed

- Prepared projects retain `tool_operation_approval` for direct and transitive
  imports of protected tools, including installed packages.
- A protected call consumes one `max_tool_calls` unit across approval and resume.
- A refused project entry reports `ProjectEntrypointNotAllowed`.
- An occupied effect journal reports `EffectJournalBusy`.
- Strict supply-chain admission recognizes the matching 1.3.1 SDK metadata.
- Resource bindings remain available after a human approval pause.
- Effect-journal diagnostics identify the explicit JSON-to-SQLite migration.
- Python preparation identifies linked virtual environments and SDK paths.

## Security And Governance

Every resumed call retains cancellation, authority, checkpoint and host-limit
checks. A second call consumes another budget unit; concurrent branches share
the same limit. Diagnostics expose controlled codes without private paths or
raw exception messages. Journal leases and single-use approvals remain enforced.

## Breaking Changes

When updating from 1.1.0, update the runtime and handler SDKs together: older
closed-schema SDKs can reject the new `execution_context` field. New tool
approval AIR requires a runtime supporting `tool_operation_approval`.
Unknown manifest and host configuration fields previously ignored are now
refused. Correct misspelled or unsupported fields before preparing a project.
Applications matching generic admission errors should also handle the precise
diagnostic codes above. There is no additional breaking change from 1.3.0.

## Migration

1. Preserve project data. Finish or reconcile suspended executions with their
   original build and checkpoints.
2. Run `touba update`, or install the archive for your platform.
3. Stop application services before updating their dependencies. In each
   project, run `touba sdk install javascript` or
   `touba sdk install python --manager uv`, according to its handler language.
   Python also supports the documented pip manager.
4. Run `touba prepare --mode write` and address configuration diagnostics.
5. Restart the application services and verify the business workflow.

For an existing JSON effect journal, use the documented migration preview and
apply commands to create a new `.effect-journal.sqlite` store. Retain the
original journal and its associated checkpoint and approval stores.
An occupied journal stays protected: wait for its owning run to release it.

## Validation Evidence

The source corrections passed 265 targeted runtime, CLI and JavaScript SDK
tests, 71 installed Python SDK tests and three isolated passes of the eight
independent minimal reproductions. Additional import controls cover unprotected
tools in the same module/package. Archive and native editor qualification are
recorded separately in each local build receipt.

## Known Limits

Tool approval resumes through human checkpoints, including server restart.
The linear `RESUME-1` profile rejects this nested continuation before effects.
Business vendor/amount validation and cross-run invoice uniqueness remain
application-service rules. An interrupted external operation requires
reconciliation with its service. Suspended executions are not migrated
automatically. Native Windows confinement and Windows publisher signing
remain outside this update; the installation guide covers SmartScreen.
